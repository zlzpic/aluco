# ADR-0001: Use EMQX Instead of a Self-Built MQTT Broker

**Status**: Accepted  
**Date**: 2024-07-18

## Context

Aluco requires an MQTT broker for device telemetry ingestion. The team considered building a minimal broker versus adopting an existing solution.

## Decision

Use **EMQX 5.8.x** as the MQTT broker.

## Consequences

### Positive
- Battle-tested at scale (millions of concurrent connections in production).
- Built-in Dashboard for debugging (port 18083).
- Supports MQTT 5.0 and 3.1.1.
- Built-in authentication and ACL (v1 uses anonymous mode; v2 introduces built-in auth).
- Active open-source project with Apache 2.0 license.

### Negative
- 5.8.x is the **last Apache 2.0 major line**; 5.9+ moved to a non-Apache license.
- Adds an operational dependency (Docker container).
- Requires memory budget (~200 MB for modest workloads).

### Neutral
- Docker Compose deployment is simplified by a single official image.
- No custom broker code to maintain.
