# ADR-0009: Introducing Kafka at the Telemetry Edge

**Status**: Accepted (pending Phase 0 benchmark data)  
**Date**: 2024-08-06

## Context

v1 uses `InMemoryTelemetrySink` (ArrayBlockingQueue + single consumer thread) for telemetry fan-out. Phase 0 benchmarks will measure at which device count the sink queue overflows or e2e latency exceeds 1s p99.

## Decision

Kafka is introduced **only if** Phase 0 benchmarks trigger the pre-registered gate (v2 spec §4.5.4):
- `aluco.sink.dropped` counter grows > 0 at any level, OR
- `aluco.e2e.latency` p99 > 1s at 10k devices × 1Hz.

**Pre-registered topology** (if triggered):
- KRaft single-node cluster (no ZooKeeper)
- Topic `aluco.telemetry` (6 partitions, key=deviceKey for per-device ordering)
- DLQ topic `aluco.telemetry.dlq` (messages failing 3 consecutive consumer retries)
- Producer acks=all, enable.idempotence=true
- Consumer group `aluco-server`, at-least-once semantics, manual offset commit after batch write succeeds
- Idempotent write via V2 migration's unique key `uk_dev_metric_ts`

## Consequences

### Positive (if triggered)
- Decouples ingestion from processing: MQTT ingest writes to Kafka without blocking on batch insert.
- Natural buffering: Kafka absorbs traffic spikes without backpressure to MQTT broker.
- Replay capability: historical data can be re-consumed for recovery or analytics.
- DLQ provides visibility into persistent processing failures.

### Negative
- **Operational overhead**: Kafka cluster to monitor, tune, and backup.
- **Increased latency**: one additional hop (MQTT → Kafka → MySQL) adds ~10-50ms.
- **Idempotency requirement**: at-least-once means duplicate writes; requires unique key enforcement.

### Neutral
- If benchmarks do NOT trigger the gate, Kafka is deferred to v3 or until explicit re-evaluation.
- The `TelemetrySink` interface is the seam; implementation swap requires no business logic changes.

## Benchmark Gate (Pre-Registered)

| Condition | Trigger Action |
|---|---|
| `sink.dropped` > 0 (any level) | Switch to Kafka |
| e2e p99 > 1s at 10k devices | Switch to Kafka |
