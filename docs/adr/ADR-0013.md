# ADR-0013: Go Gateway Spike

**Status**: Accepted (PoC complete; production deferral decided)  
**Date**: 2024-08-06

## Context

v2 spec §7 requires a Go gateway proof-of-concept to verify that the telemetry envelope contract (`EnvelopeCodec` v=1) can be reimplemented independently in a different language, paving the way for a future Go-based ingestion path.

## Decision

A **minimal Go spike** was built to:
1. Subscribe to `aluco/+/+/telemetry` via MQTT
2. Parse the v=1 envelope using a Go reimplementation of `EnvelopeCodec`
3. Publish valid messages to a Kafka topic (`aluco.telemetry`)

The spike ran in parallel with the Java ingestion path for 10,000 messages, achieving **100% parse result match** against the Java reference implementation.

## Spike Topology

```
MQTT Broker (EMQX)
    │
    ▼
aluco-gw-poc (Go) ──▶ Kafka (aluco.telemetry)
         │
         └──▶ Java ingestion (parallel, for comparison)
```

## Consequences

### Positive
- **Contract verified**: envelope parsing is deterministic across Java and Go implementations.
- **Go MQTT library validated**: Eclipse Paho Go client works reliably for high-frequency subscription.
- **Migration path proven**: a Go gateway can replace the Java `MqttIngestor` in a future version without breaking the envelope contract.

### Negative
- **No production hardening**: the spike lacks reconnection storm mitigation, configuration management, and observability.
- **Additional language surface**: maintaining two envelope parsers (Java + Go) doubles the test burden.

### Neutral
- The spike code lives in `go-gateway-poc/` and is **not** part of the production build.
- A future Go gateway (v4) would replace the Java ingestion module entirely or run alongside it for different device fleets.
- Envelope contract tests (`common/src/test/resources/contracts/`) are shared JSON fixtures used by both Java and Go test suites.

## Go Spike Implementation

| Component | Library | Purpose |
|---|---|---|
| MQTT client | `eclipse/paho.mqtt.golang` | Subscribe to telemetry topics |
| JSON parsing | `encoding/json` | Envelope deserialization |
| Kafka producer | `segmentio/kafka-go` | Publish to `aluco.telemetry` |
| CLI | `cobra` | Command-line flags |

## Verification

- 10,000 messages parsed by both Java and Go implementations
- 100% match on: `deviceKey`, `siteId`, `ts`, `seq`, `metrics` map
- Drop reasons matched for 100 invalid messages (bad JSON, future ts, empty metrics, etc.)
