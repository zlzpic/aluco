# ADR-0003: Anonymous MQTT in v1 with App-Layer Device Validation

**Status**: Accepted  
**Date**: 2024-07-18

## Context

v1 needs a device authentication mechanism for MQTT connections. Full EMQX authentication adds operational complexity (credential lifecycle, ACL rules) that conflicts with the v1 goal of a quick, demonstrable system.

## Decision

Run EMQX in **anonymous mode** (`EMQX_ALLOW_ANONYMOUS=true`) for v1. Device identity is validated at the application layer: the server checks `device_token` against the `device` table and drops messages from unregistered devices.

## Consequences

### Positive
- Zero broker credential management in v1.
- Simulator and devices can connect without pre-provisioned credentials.
- Faster iteration; `docker compose up` is sufficient to start.

### Negative
- **No broker-level access control**: any MQTT client can publish/subscribe to any topic.
- Application-layer validation is the only gate; a bypass in `DefaultTelemetryProcessor` exposes the entire ingestion pipeline.
- Not suitable for multi-tenant or Internet-exposed deployments.

### Neutral
- `device.token` is generated and stored but unused by the broker in v1.
- v2 introduces EMQX built-in auth + ACL (see ADR-0007).

## Hardening Path (v2)

1. Enable `EMQX_ALLOW_ANONYMOUS=false`.
2. Configure EMQX built-in database authenticator (`password_based:built_in_database`).
3. Server bootstraps EMQX credentials via EMQX REST API (`/api/v5/authentication`).
4. ACL rules: `{username}` placeholder scopes publish/subscribe to device's own topics.
5. Token rotation invalidates old broker credentials immediately.
