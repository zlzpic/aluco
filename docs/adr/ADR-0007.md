# ADR-0007: EMQX Built-in Authentication/Authorization with Token-as-Password

**Status**: Accepted  
**Date**: 2024-08-06

## Context

v1 runs EMQX in anonymous mode (ADR-0003). The `device.token` column is generated and stored but unused by the broker. v2 introduces broker-level access control: only registered devices with valid credentials may connect and publish to their own topics.

## Decision

Use **EMQX 5.8.x built-in database** (`password_based:built_in_database`) for authentication, with `aluco.mqtt.auth=on` (default) in v2. Device credentials are: `username = device_key`, `password = device.token`. The server bootstraps and reconciles EMQX users via the EMQX REST API at startup and on device lifecycle events (create/delete/token-rotate).

## Consequences

### Positive
- **Broker-level access control**: unregistered devices cannot publish to telemetry topics.
- **Per-device credential isolation**: each device can only publish/subscribe to its own scoped topics via ACL rules.
- **Immediate token revocation**: `EmqxAuthService.rotateDeviceCredential()` deletes and re-creates the EMQX user, invalidating the old token instantly.
- **Graceful degradation**: if EMQX is unreachable, the server logs WARN and falls back to application-layer validation (same as v1), not blocking startup.

### Negative
- **Operational complexity**: server now depends on EMQX REST API availability during device CRUD operations.
- **Credential sync race condition**: if device creation succeeds in MySQL but EMQX user creation fails, the device cannot connect until the next reconciliation cycle.
- **Dual write burden**: device token is stored in MySQL and EMQX; consistency requires careful error handling.

### Neutral
- v2 introduces `aluco.mqtt.auth=on|off` profile switch. `off` mode is for development environments without EMQX (anonymous broker, app-layer validation only).
- ACL rules use `{username}` placeholder: devices can only `publish aluco/+/{deviceKey}/telemetry`, `publish aluco/+/{deviceKey}/cmdack`, and `subscribe aluco/+/{deviceKey}/cmd`.
- The `aluco-server` superuser (username from `ALUCO_EMQX_API_USER`) has `allow all aluco/#` for admin operations.

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `ALUCO_MQTT_AUTH` | `on` | `on` = EMQX auth enabled; `off` = insecure dev mode |
| `ALUCO_EMQX_API_BASE` | `http://localhost:18083` | EMQX Dashboard URL |
| `ALUCO_EMQX_API_USER` | `admin` | Dashboard API user |
| `ALUCO_EMQX_API_PASSWORD` | `public` | Dashboard API password |
